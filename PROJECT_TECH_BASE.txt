1. PROJECT OVERVIEW & CORE MISSION
================================================================================
Power Afric Store (Power Afric Energy Services LTD) is Nigeria's enterprise
solar and renewable energy e-commerce platform and operational portal.

The application handles three distinct user-facing spheres:
  A. Public Customer Marketplace: Browsing solar panels, inverters, batteries,
     accessories, and installation services with cart, wishlist, checkout, and
     order tracking.
  B. Sales Agent Portal (/sales): Dedicated CRM workspace for internal sales
     representatives to manage custom quotations, visual catalogue picker,
     customer invoices, product lookup, and agent profile settings.
  C. Super Admin & Staff Portal (/admin): Enterprise control center managing
     users, pipeline orders, assignment to staff, service management, inventory
     catalogue, executive analytics, and invoice auditing.

Key Business Attributes:
  - Base Currency: Nigerian Naira (NGN / ₦).
  - Tax Policy: All storefront product prices are strictly VAT-inclusive.
    Invoices generated from the Invoices Tab feature NO additional VAT line item
    (VAT rate = 0%, VAT amount = 0, Grand Total = Subtotal - Discount).
  - Default Corporate Bank:
      Bank Name: GTBank Plc.
      Account Name: Power Afric Energy Serv. LTD
      Account Number: 0500647850

4. DATABASE ARCHITECTURE & PERSISTENCE LAYER (NEON POSTGRESQL + PRISMA)
================================================================================
Database Engine:
  PostgreSQL 18.0 hosted on Neon Serverless (ep-round-hill pooler).

Connection Client Implementation (src/lib/db.ts):
  - Uses `@neondatabase/serverless` package via `neon(databaseUrl)`.
  - Connection sanitization: `cleanDatabaseUrl` strips `channel_binding=require`
    query parameter to prevent protocol negotiation handshake failures.
  - Fail-safe fallback: If `process.env.DATABASE_URL` is omitted in Vercel or local
    environments, `src/lib/db.ts` embeds a verified direct connection string so
    the application never crashes on unconfigured deployments.
  - Retry Architecture: `executeWithRetry(fn, maxRetries = 3, baseDelayMs = 400)`
    automatically traps transient network glitches ('fetch failed', 'ECONNRESET',
    'ETIMEDOUT', 'timeout') and applies exponential backoff.

Database Tables:
  1. "User" Table:
     Columns: id (VARCHAR PK), email (UNIQUE), firstName, lastName, avatar,
     emailVerified, phone, role ("customer" | "sales_agent" | "staff" | "superadmin"),
     password (bcrypt hashed), createdAt, updatedAt, lastLogin, isActive, permissions.

  2. "Order" Table:
     Columns: id (SERIAL PK), userId, orderNumber (UNIQUE), items (JSONB),
     subtotal (NUMERIC), shipping (NUMERIC), tax (NUMERIC), total (NUMERIC),
     status (VARCHAR), shippingAddress (JSONB), billingAddress (JSONB),
     paymentMethod (VARCHAR), paymentStatus (VARCHAR), trackingNumber,
     estimatedDelivery, actualDelivery, notes, createdAt, updatedAt.

  3. "Invoice" Table (Created via scripts/create-invoice-table.js):
     Columns: id (SERIAL PK), "invoiceNumber" (VARCHAR UNIQUE), "customerName",
     "customerEmail", "customerPhone", "customerAddress", "issueDate" (DATE),
     "dueDate" (DATE), "items" (JSONB), "subtotal" (DECIMAL 14,2),
     "taxRate" (DECIMAL 5,2 DEFAULT 0), "taxAmount" (DECIMAL 14,2 DEFAULT 0),
     "discount" (DECIMAL 14,2 DEFAULT 0), "total" (DECIMAL 14,2), "status",
     "paymentMethod", "bankName", "accountName", "accountNumber", "notes",
     "terms", "createdBy", "creatorName", "creatorEmail", "creatorRole",
     "createdAt", "updatedAt".

  4. "Address" Table:
     User saved delivery addresses with coordinates and defaults.

  5. "WishlistItem" Table:
     Customer bookmarked solar equipment for quick re-ordering.

6. STATE MANAGEMENT ARCHITECTURE (ZUSTAND 5)
================================================================================
All primary frontend state is orchestrated using Zustand 5 with browser
`localStorage` persistence.

1. `useAuthStore` (src/lib/stores/authStore.ts):
   - Key: 'power_afric_auth'
   - State: user (User | null), isAuthenticated (boolean), loading (boolean).
   - Methods: login(credentials), register(userData), logout(), checkAuth(),
     updateUser(partialUser).
   - Features: Stores active JWT/session and role for instant client-side RBAC.

2. `useCartStore` (src/lib/stores/cartStore.ts):
   - Key: 'power_afric_cart'
   - State:
       items: CartItem[] (Products & Services)
       accessories: CartItem[] (Installation hardware)
       editingOrderId: number | null
       editingOrderNumber: string | null
       editingOrderBackup: backup cart snapshot
       editingShippingAddress: any
       editingPaymentMethod: string | null
   - Methods:
       addItem(product, qty)
       removeItem(id, type)
       updateQuantity(id, qty, type)
       addAccessory(acc, qty)
       removeAccessory(id)
       updateAccessoryQuantity(id, qty)
       setService(service, qty)
       clearCart()
       startEditingOrder(order)
       cancelEditingOrder()
       finishEditingOrder()
       Calculators: getTotalPrice, getProductTotal, getServiceTotal, getAccessoriesTotal, getGrandTotal.

3. `useNotificationStore` (src/lib/stores/notificationStore.ts):
   - Global notification dispatcher supporting 'success', 'error', 'warning', 'info'.
   - Integrated Bridge: Every call to `addNotification(...)` automatically executes
     `react-hot-toast` (`toast.success`, `toast.error`, etc.), guaranteeing dual
     visibility on both the floating bottom banner and high-z-index top-right toasts.

4. `useServiceStore` (src/lib/stores/serviceStore.ts):
   - Caches solar installation service packages (Standard, Premium, Industrial).

5. `useAccessoryStore` (src/lib/stores/accessoryStore.ts):
   - Caches DC cables, battery racks, breakers, surge protectors, and mounting rails.

6. `useUserProfileStore` (src/lib/stores/userStore.ts):
   - Key: 'power_afric_user_profile'
   - Manages live customer order cache, active order updates, and saved addresses.

7. AUTHENTICATION, AUTHORIZATION & RBAC SYSTEM
================================================================================
Supported Roles:
  1. `superadmin`:
     - Full operational control over /admin, /sales, and customer views.
     - Can delete users, assign orders to staff, modify global catalog, and issue invoices.
  2. `staff`:
     - Order processing agent assigned to fulfill pending customer orders and updates.
  3. `sales_agent`:
     - Access to /sales portal.
     - Can generate professional invoices, pick catalog items, customize service prices,
       and monitor client transaction progress.
  4. `customer`:
     - Standard public consumer with access to cart, checkout, profile, and orders.

Route Guard Implementation:
  - Admin Layout (`src/app/admin/layout.tsx`):
    Validates `isAuthenticated && (user.role === 'superadmin' || user.role === 'staff')`.
    Redirects unprivileged visitors to root `/` with login trigger.
  - Sales Layout (`src/app/sales/layout.tsx`):
    Validates `isAuthenticated && (user.role === 'sales_agent' || user.role === 'superadmin')`.
  - Customer Checkout Guard:
    Checks session authentication before allowing order submission; saves cart to
    localStorage (`checkout_cart`) and opens login modal if unauthenticated.

9. THE 3-PHASE E-COMMERCE ENGINE (PRODUCTS, ACCESSORIES, SERVICES)
================================================================================
A core innovation of the Power Afric platform is the strict 3-Phase segregation
of order items to guarantee crystal-clear invoicing without name-based guessing:

Phase 1: Products (Solar Panels, Inverters, Lithium Batteries)
  - Identified by `item.type === 'product'` or absence of `serviceId` / `accessoryId`.
  - Unit pricing includes manufacturer warranty terms.

Phase 2: Accessories (Cables, Breakers, Mounting Rails, Lugs)
  - Identified by `item.type === 'accessory'` or `item.accessoryId != null`.
  - Quantified by units (meters, pieces, sets).
  - Selected via `AccessorySelectionPopup.tsx` modal directly in cart/checkout.

Phase 3: Services (Site Inspection, Installation, Maintenance)
  - Identified by `item.type === 'service'` or `item.serviceId != null`.
  - Bound to the primary system installation scope.

Order Editing Workflow:
  Customers with `pending` orders can click "Edit Order" in their account history.
  The system saves the current cart, loads the existing order into `useCartStore`,
  locks the interface into `editingOrderId` mode, and submits changes via `PATCH /api/orders/[id]`.

10. INVOICE MANAGEMENT & PRINTABLE TEMPLATE SYSTEM (ZERO-VAT MODEL)
================================================================================
Shared Component:
  `src/components/admin/invoices/InvoiceManager.tsx` powers both:
    1. Super Admin Invoices (`/admin/invoices`)
    2. Sales Agent Invoices (`/sales/dashboard?tab=invoices`)

Zero-VAT Corporate Policy:
  - VAT Rate is strictly fixed at 0.00%.
  - VAT Amount is strictly ₦0.00.
  - Grand Total = Subtotal - Discount.
  - The VAT input row and VAT calculation rows are suppressed in the creation modal.
  - The Summary Breakdown in the printable invoice template completely omits the VAT row.

Printable Invoice Engine (`src/lib/services/invoiceTemplate.ts`):
  - Function `openPowerAfricInvoice(rawInvoiceOrOrder)`:
      1. Normalizes data via `normalizeToUnifiedInvoice`.
      2. Generates dynamic QR code for verification.
      3. Compiles self-contained HTML document with custom CSS styles.
      4. Opens high-resolution printable browser window via `window.open`.
  - Format includes:
      - Power Afric corporate header with logo and contact information.
      - Customer billing and delivery metadata.
      - 3-Phase segregated itemized tables (Products, Accessories, Services).
      - Invoice Summary table (Products Total, Accessories Total, Services Total, Discount, Grand Total).
      - Verified GTBank payment details.
      - Corporate terms and conditions.

14. CRITICAL BUSINESS LOGIC RULES & TAX CALCULATIONS
================================================================================
Rule 1: Zero VAT on Invoices
  - When calculating invoice totals in backend or frontend:
      `subtotal = SUM(quantity * unitPrice)`
      `discountAmount = Math.max(0, discount)`
      `discountedSubtotal = Math.max(0, subtotal - discountAmount)`
      `taxRate = 0`
      `taxAmount = 0`
      `total = discountedSubtotal`
  - Never add 7.5% or 8% to generated invoices. Storefront products are already VAT-inclusive.

Rule 2: Order Item Idempotency
  - When line items are added to orders, unique `lineItemId` strings are generated
    (`product_${timestamp}_${rand}`) to prevent accidental duplicate key merging in React.

Rule 3: Creator Attribution
  - Every invoice records `createdBy` (user ID), `creatorName`, `creatorEmail`, and `creatorRole`.
  - When sales agents view the Invoices tab, records are filtered by their `salesAgentId`.
  - Super admins can view all invoices or filter by creator.

15. COMMON PITFALLS, SANDBOX CONSTRAINTS & DEVELOPMENT GUIDELINES
================================================================================
Guideline 1: Windows Line Endings (CRLF vs LF)
  - When making string edits in files like `InvoiceManager.tsx`, be mindful that
    files on Windows may have CRLF (`\r\n`). Single-line string replacements or
    clean AST edits are strongly preferred to avoid line-break mismatch errors.

Guideline 2: TypeScript Non-Incremental Build Verification
  - Because `tsconfig.tsbuildinfo` may encounter EPERM write restrictions in some
    sandboxed environments, always run verification with:
      `npx tsc --noEmit --incremental false`

Guideline 3: Toast Notification Consistency
  - When creating any interactive button or mutation (adding to cart, deleting an item,
    submitting a form), always provide immediate visual feedback using `react-hot-toast`
    (`toast.success(...)`, `toast.error(...)`, `toast(...)`).

Guideline 4: Database Connection Pool Safeguards
  - Never remove the `executeWithRetry` wrapper in `src/lib/db.ts`. Serverless
    database connections can experience transient cold-start latency; the retry
    wrapper ensures seamless recovery.
